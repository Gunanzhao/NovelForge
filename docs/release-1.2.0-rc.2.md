# NovelForge 1.2.0-rc.2 — 草稿恢复与数据可靠性

本版在 1.2.0-rc.1 基础上加强异常退出、存储故障及恢复流程的保护，仍为 Windows x64 预发布版本。

## 本次更新

- **独立草稿快照**：每 10 秒尝试保存正文与已注册资料表单，持续输入不重置计时。欢迎页和数据设置可查看、对照、复制或导出恢复稿；旧版本的保存确认不会删除更新的草稿。
- **界面异常保护**：校验并限制最近项目缓存；界面渲染失败时保留编辑状态，提供正文和表单草稿的复制、导出及重试入口。
- **保守恢复与格式兼容**：数据库锁定、权限、磁盘满和 I/O 错误不会被当作数据库损坏重建。损坏或不一致的操作日志保留原证据并阻止正常写入，可通过救援入口导出安全可读正文。未知新版项目格式或数据库结构在写入前被拒绝。
- **明确确认的历史清理**：查看占用并预览后，仅清理符合条件的旧自动历史，保留最新、命名与保护版本；中断后可以按日志恢复，缺失历史仍会阻止不完整备份。
- **启动诊断与恢复副本**：Windows 无终端启动失败时显示原生提示；脱敏日志记录启动阶段，恢复副本使用唯一名称，降低快速连续保存时的碰撞风险。
- **真实 Windows IPC 门禁**：覆盖生产 EXE、Unicode 与序列化契约、项目重开、外部修改冲突、恢复副本、备份还原、正文导出和强制重启。修复高权限进程下环境变量调试参数被 WebView2 忽略的问题，改为显式诊断模式通过原生 API 设置；正常启动默认不开启 CDP。CI 保留失败结果并上传脱敏诊断。
- 更新 brace-expansion 的间接依赖补丁版本；保留既有 GLib 安全回补及审计检查。

## 验收依据

可靠性代码基线 `4c0fc02ce43db623394269a575b8f282be542494` 的 [CI #172](https://github.com/Gunanzhao/NovelForge/actions/runs/36802439384) 中，Frontend checks、Rust checks 和 Windows reliability 全部通过。前端 491 项、Windows Rust 174 项测试通过，7 项原有按需测试仍忽略。

远端生产 EXE 首次 CDP 连接 3966 ms、强制重启后 783 ms，完整数据生命周期断言通过。本地端口占用负向测试仍正确失败；没有跳过 IPC、放宽断言或使用 continue-on-error。发布版本及资产的确切提交、CI 和校验信息见 GitHub Release 附加记录。

## 升级与使用范围

- 升级前建议创建完整项目备份。已有安装版运行本版安装包升级；独立 EXE 不更新原有快捷方式。需要 Windows WebView2，下载后可使用 SHA256SUMS.txt 校验。
- 独立草稿保存在本机应用数据目录，保护到最后一次成功写入，不保证零丢失、断电安全或挂起期间写入。单份上限 2 MiB、最多 100 个目标、合计 50 MiB（含替换空间）；失败会提示，不自动淘汰其他待恢复草稿。超限内容需手动导出；浏览器演示仅有内存快照。
- 恢复稿不会静默覆盖正文。缺少原始一致性证据时，不直接解锁有问题的项目；救援导出不等于完整项目恢复。
- 历史不自动清理；SQLite 释放页可复用，不保证数据库文件立即缩小。项目备份与独立草稿用途不同，同盘备份不能防止整盘损坏。
- 本版未执行付费或真实账号 AI 生成，也未重新执行 rc.1 的完整截图布局矩阵；既有 DOCX 正文图片、PDF 富格式限制继续适用。Linux 原生启动失败提示尚未实现。
