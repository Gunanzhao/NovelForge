# 写作流程增强：实现与验收清单

目标：完成六项功能；每个可验证改动单独提交，全部完成和验收后统一推送。基线 4148c24。保留现有本地文档改动，不自动发布新版本或替换安装。

## 完整范围

- [ ] F1 资料版本历史：人物/地点/世界观/附件说明自动记录；命名版本；字段差异；整条/字段恢复；保护恢复前版本；项目/条目/内容冲突检查；备份往返保留。
- [ ] F2 Wiki 安全改名：明确引用影响预览（正文及规划资料）；选择更新位置；旧名别名；普通同名文字仅候选；代码和排除区不替换；批量保护及整体撤销；同名歧义与迟到/内容冲突检查。
- [ ] F3 自动备份与恢复中心：用户选择独立目录；按日/写作会话触发，仅有变化才执行；成功/失败/空间状态；保留数量与清理预览；正文保存/历史/独立备份分别显示；恢复到新目录并验证；孤立恢复内容可查看/复制/另存章节。
- [ ] F4 正文批注与修订任务：选区添加；随编辑映射；原文删除后失联标记；待处理/已解决/分类筛选；全书列表和定位；持久化/恢复/项目切换安全。
- [ ] F5 章节摘要与故事记忆：关键事件、人物知识、关系身份物品变化、伏笔和承接项；作者确认才纳入记忆；正文变更后过期提示；来源段落定位；AI 上下文引用已确认记录并显示来源；疑点审阅，不自动认定或改写正文。
- [ ] F6 稿件导入：TXT/Markdown 文件；编码验证；章标题识别和可调整分章预览；确认后创建；重复名称/失败回滚/原项目保护；导入后可编辑、搜索和备份。DOCX 不在本阶段。

## 共同要求

- 保持本地优先、Tauri/React/SQLite 技术栈；桌面与浏览器演示行为明确。
- 写操作校验当前项目、目标、版本和未保存稿件；确认前可审阅，不发送真实稿件进行测试。
- 每个逻辑改动运行针对性回归并记录提交；最后全量前端/Rust检查、生产构建和真实桌面验收。
- 最后统一推送验证分支，通过云端CI后快进main。不得用部分完成替代六项完整目标。
