# NovelForge rc.4 全量复核报告

日期：2026-09-06（Asia/Shanghai）
源码基线：`946fdada0c1059760e7a2affb426a468869499c9`，`v1.1.0-rc.4`
验收基线：当前 README、SPEC、Codex 接入文档，以及界面显示的功能描述。
方法：源码审阅、完整前后端回归、已安装 Windows 程序的 CDP 工作流、原生窗口关闭验证、三尺寸截图、受控异步与文件系统故障注入。

## 结论

常见工作流和原有回归测试通过，但不能判定“所有功能均可用且与描述相符”。本轮确认 **11 项问题：4 项 P1、6 项 P2、1 项 P3**。其中 10 项有定向运行或界面证据，Temperature=0 问题由确定性的源码逻辑确认。另有“锁定”状态的语义需要明确。

优先处理正文保存/关闭、章节选择时序、跨项目异步响应、父子节点回收站恢复，再修复导出完整性和界面问题。在这些 P1 问题解决前，不建议把 rc.4 宣布为完成数据可靠性验收的稳定版。

本轮交付审计报告和复现材料，未实施产品修复。业务源码、依赖、既有测试、Git 提交和远端 Release 均保持在上述基线。所有故障注入仅作用于本轮创建的合成项目。

## 确认的问题

### NF-AUDIT-01 / P1：保存失败时，系统关闭窗口仍直接丢弃正文

- 复现：在独立项目保留原正文备份，用同名空目录模拟正文路径不可写；输入 `UNSAVED_CLOSE_SENTINEL_20260906`，等待自动保存报错，再点击 Windows 标题栏关闭按钮。
- 实际：窗口和进程正常退出，未出现保留/另存/放弃修改的确认；恢复文件数量为 0，原正文中不存在新输入。故障注入结束后已恢复测试项目原正文路径。
- 原因：前端只有 900 ms 防抖自动保存；没有窗口关闭拦截。Rust 窗口事件只处理 `Destroyed` 时的 Codex 清理。保存函数还会在写恢复文件之前读取旧正文，这一步失败时没有恢复副本。
- 位置：[App.tsx](D:/NovelForge/src/App.tsx:130)、[lib.rs](D:/NovelForge/src-tauri/src/lib.rs:10)、[manuscript.rs](D:/NovelForge/src-tauri/src/commands/manuscript.rs:797)。
- 建议：统一关闭项目/关闭窗口的保存流程；保存失败时阻止默认退出，提供复制、另存或明确放弃；审查恢复副本写入时机。
- 证据：[close-evidence.json](D:/NovelForge/docs/audits/rc4/close-evidence.json)。本轮实测的是“保存失败后正常关闭”，不是强制结束进程。900 ms 窗口内退出的风险由同一缺失的关闭保护机制推导。

### NF-AUDIT-02 / P1：迟到的章节读取响应覆盖后续编辑

- 复现：从 A 选择 B，令 B 读取延迟；随后选择 A 并编辑；最后返回 B 的旧读取结果。
- 实际：当前文档被 B 替换，新输入消失，保存状态被标记为 `saved`。
- 原因：`selectNode` 返回时只检查项目路径，没有检查最新选择请求、当前文档版本或仍待保存的内容。
- 位置：[app-store.ts](D:/NovelForge/src/stores/app-store.ts:253)。
- 建议：为章节选择增加请求序号和版本校验；迟到响应不得覆盖新选择或新编辑。
- 证据：定向测试 `AUDIT-01` 期望 `new user edits`，实际得到 `B content`。

### NF-AUDIT-03 / P1：旧项目的异步修改结果写入新项目状态

- 复现：在 P 项目保存人物，延迟保存响应；切换到 Q 项目；返回 P 的保存结果。
- 实际：`projectPath` 仍为 Q，但 `data.project.id` 被替换为 P。界面显示的数据和后续命令目标不再属于同一项目。
- 原因：`saveEntity` 等修改入口调用无项目归属校验的 `refreshData`。类似模式还存在于创建、重命名、删除、移动、附件导入等入口；本轮定向复现使用人物保存。
- 位置：[app-store.ts](D:/NovelForge/src/stores/app-store.ts:317)、[saveEntity](D:/NovelForge/src/stores/app-store.ts:411)。
- 建议：所有异步修改绑定项目路径、项目 ID 和项目会话序号；只让当前项目会话接收响应。统一处理过期错误、统计和回收站结果。
- 证据：定向测试 `AUDIT-02` 期望项目 `q`，实际为 `p`。跨项目进一步写坏文件是风险推断，本轮没有对用户项目执行该后续步骤。

### NF-AUDIT-04 / P1：恢复父节点会错误激活此前独立删除的子节点

- 复现：先删除章节 C，再删除其卷 V，最后从回收站恢复 V。
- 实际：C 出现在活动正文树，但读取报“系统找不到指定的文件”；从回收站恢复 C 又报“节点不在回收站”。C 的原文件仍在独立的回收站位置。
- 原因：恢复时从包含已删除记录的全部节点收集后代，并无条件清除后代的删除标记，没有区分同一删除批次与此前独立删除的子树。
- 位置：[trash.rs](D:/NovelForge/src-tauri/src/commands/trash.rs:67)、[后代恢复](D:/NovelForge/src-tauri/src/commands/trash.rs:148)。
- 建议：只恢复与父节点同批删除、且实际位于父节点隔离目录中的后代；保持独立回收站条目的状态与恢复路径一致。永久删除父节点也需要对应组合回归。
- 证据：[backend-evidence.json](D:/NovelForge/docs/audits/rc4/backend-evidence.json) 的 `delete-child-delete-parent-restore-parent`。本次是“界面无法恢复”，不表示回收站中的原文件已物理丢失。

### NF-AUDIT-05 / P2：导出会删除正文中的一级标题和代码内容

- 复现：正文中加入内部标题 `# 正文内部标题`，并在 fenced code 中加入 `# CODE_SENTINEL`，分别导出 Markdown、TXT、HTML。
- 实际：三种输出都缺少这两行，导出仍返回成功。
- 原因：公共导出准备阶段过滤全部 `trim_start().starts_with("# ")` 行，未区分章节标题、正文标题或代码块。六种导出共用该 Markdown 准备路径，因此其他格式也受相同过滤逻辑影响；本轮直接检查了上述三种输出。
- 位置：[export.rs](D:/NovelForge/src-tauri/src/commands/export.rs:52)。
- 建议：仅在确认匹配时消除开头重复的章节标题；保留正文其余标题和代码块，使用解析结构而非逐行无条件过滤。
- 证据：`backend-evidence.json` 的三个 `export-content` 项；两类哨兵均为 `false`。与界面“保留标题层级和 Markdown 语法”的描述不符。

### NF-AUDIT-06 / P2：导出没有等待当前正文保存

- 复现：当前文档有未保存修改，立即调用工作台导出；保存失败但仍保留新正文时也会发生同一问题。
- 实际：调用顺序只有 `export`，没有 `save`；后端读取磁盘上的旧正文。
- 位置：[app-store.ts](D:/NovelForge/src/stores/app-store.ts:485)。
- 建议：导出前等待统一保存协调器完成，失败时中止或明确选择导出已保存版本；不要以成功提示隐瞒版本差异。
- 证据：定向测试 `AUDIT-03`，预期 `['save','export']`，实际 `['export']`。

### NF-AUDIT-07 / P2：新建资料连续保存会重复建档

- 复现：新建人物“林月”，保存成功后继续点击“保存资料”。
- 实际：第二次保存的 `id` 仍为 `null`，后端按新建处理，产生重复条目。
- 原因：保存后仍执行 `selectEntity(kind, selected?.id ?? null)`；新建时 `selected` 为空，没有选中服务端生成的新实体 ID。
- 位置：[EntityView.tsx](D:/NovelForge/src/components/EntityView.tsx:182)。
- 建议：保存入口返回明确的新建实体 ID，保存后切换到该条目的编辑状态；相关资料类型一起回归。
- 证据：组件复现 `AUDIT-04`，第二次保存期望 `new-character`，实际 `null`。

### NF-AUDIT-08 / P2：数据库重建后，附件资料与说明消失

- 复现：导入参考文件并填写说明，保留数据库副本后移走当前数据库，重新打开项目触发镜像重建。
- 实际：附件记录从 1 条变为 0 条，原始附件文件仍存在；界面无法通过资料附件列表访问原说明和关联。
- 原因：附件跳过资料 Markdown 镜像写入，重建资料的目录列表也没有附件处理逻辑。
- 位置：[entities.rs](D:/NovelForge/src-tauri/src/commands/entities.rs:35)、[重建资料](D:/NovelForge/src-tauri/src/commands/mod.rs:660)。
- 建议：为附件元数据提供独立可恢复镜像，或明确提示附件元数据未恢复并提供导入/重建入口；保留二进制文件不应被表述为全部资料已恢复。
- 证据：`backend-evidence.json` 的 `attachment-after-rebuild`：`beforeCount=1`、`afterCount=0`、`originalFileExists=true`。原数据库副本保留在合成项目内。

### NF-AUDIT-09 / P2：支持的最小窗口尺寸裁掉右侧操作

- 环境：已安装 rc.4 的 WebView2，CDP 分别设置内容视口 `1440×900`、`1366×768`、`1100×650`。配置允许最小窗口宽度 1100、高度 650。
- 实际：1100 宽度下 `document.body.scrollWidth=1223`，辅助栏和顶部操作超出右边界。辅助栏切换按钮 x≈1108，主题按钮 x≈1142，设置按钮 x≈1176，均超过视口；`body overflow:hidden` 使这些控件无法通过页面横向滚动找回。
- 位置：[index.css](D:/NovelForge/src/index.css:61)、[topbar](D:/NovelForge/src/index.css:68)、[tauri.conf.json](D:/NovelForge/src-tauri/tauri.conf.json:18)。
- 建议：按可用宽度折叠顶部次要按钮、收起辅助栏，约束主网格的最小内容宽度；进一步验收缩放和左右栏最大宽度组合。
- 证据：[1100 宽截图](D:/NovelForge/docs/audits/rc4/screenshots/1100-codex.png)、[布局数据](D:/NovelForge/docs/audits/rc4/layout-metrics.json)。测量使用内容视口模拟，未把它等同于全部 Windows DPI 组合实测。

### NF-AUDIT-10 / P2：Temperature 设为 0，保存和请求实际变成 0.7

- 实际逻辑：设置持久化和发送请求两处都使用 `Number.parseFloat(temperature) || 0.7`。合法值 `0` 被当作假值替换，界面显示 0 时服务端收到 0.7，重新打开也恢复为 0.7。
- 位置：[偏好保存](D:/NovelForge/src/components/AiAssistantView.tsx:121)、[Provider 请求](D:/NovelForge/src/components/AiAssistantView.tsx:163)。
- 建议：使用 `Number.isFinite` 判断无效值，保留 0，并统一输入解析函数。
- 证据等级：确定性源码审阅；本轮未单独发网络请求验证此参数，不计入四项定向失败测试。

### NF-AUDIT-11 / P3：“跟随系统”不响应运行期间的主题变化

- 复现：保持默认系统主题，使用 WebView2 媒体特性模拟从浅色变为深色。
- 实际：`matchMedia('(prefers-color-scheme: dark)').matches=true`，但 `documentElement.dataset.theme` 仍为 `light`。
- 原因：主题 Effect 只依赖 `theme`，没有订阅 `MediaQueryList` 的 `change`。
- 位置：[App.tsx](D:/NovelForge/src/App.tsx:122)。
- 建议：系统模式订阅变化事件并在清理时退订；手动浅色/深色模式不受系统变化影响。
- 证据：`layout-metrics.json` 最后一项 `system-theme-change`。未修改用户 Windows 系统主题。

## 需要明确的行为语义

“锁定”目前只是状态标签：将章节状态设为 `locked` 后，后端仍允许保存新的正文，编辑器也没有只读限制。`backend-evidence.json` 中 `locked-status` 保存了 `LOCKED_BUT_EDITED`。如果产品希望锁定防误改，应补齐所有正文写入入口的约束；如果只是进度标签，应调整文案。本项不混入上述 11 项确定缺陷。

## 安全结论与验收边界

- 本轮没有新增确认的 Markdown 脚本执行、HTTP 重定向泄露、Codex 工具越权或恢复目录越界漏洞；对应既有回归通过。没有发现不等于证明不存在漏洞。
- 新确认的主要问题属于数据完整性、保存保护和恢复可靠性，其中跨项目状态混用尤其应优先修复。
- CI Actions 仍固定完整 SHA；依赖审计、只读仓库权限、凭据忽略规则和每周依赖更新配置存在。没有执行公开写入或更改保护策略。
- 截图自动检测中的“弹窗遮住底层按钮”“内容位于可滚动区域下方”属于正常行为，已排除，不能把原始 `clipped` 数量当作缺陷数量。
- 对 51 张截图做自动几何检查，并人工复核代表性布局、最小视口与导出弹窗；不声称所有页面每个滚动位置、文本长度及操作组合均已穷举。
- 本轮未重新安装/构建完整 NSIS 包，使用上一轮已安装并验证的同一 rc.4 程序；前端生产构建已重跑。原生文件选择器、独立 Tauri WebDriver、每种导出阅读器视觉兼容性没有在本轮重跑。
- 本轮未实测 Linux/macOS；没有穷举所有 CLI/模型、第三方 Provider 和 Windows DPI/字体组合。17 条 Rust 允许警告继续保留，不能描述为“零安全警告”。
